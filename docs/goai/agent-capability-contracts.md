# Chroni Agent capability contracts

Chroni is one hybrid Agent with reusable capabilities, not a fabricated multi-Agent system. Model calls are optional candidate generators. Local code owns evidence, constraints, state changes, persistence, and fallback.

| Capability | Goal | Input | Output | Called when | Failure and local fallback | Code evidence |
| --- | --- | --- | --- | --- | --- | --- |
| `DeadlineExtraction` | Turn supported materials into deadline candidates. | `IntakePayload` with text or bounded files; fixed reference time in tests. | `ExtractResult` with extracted sources, tasks, pending candidates, failures. | Quick add, drag/drop, file upload, local API intake. | Per-file errors are isolated; deterministic rules run when LLM is absent or fails. | `intake.ts: extractPayload`, `extractFromFiles` |
| `EvidenceValidation` | Keep task facts grounded in source text and safe dates. | Candidate, source excerpt, existing tasks. | Accepted item, pending candidate, duplicate, or rejection. | After rule/model extraction and source reprocessing. | Invalid dates, conditional DDL, unsupported evidence, and duplicates cannot silently become new facts. | `deadline-text.ts`, merge/grounding functions, Store reconciliation |
| `MissingFieldClarification` | Ask only for necessary missing or conflicting facts and resume later. | `ExtractedInput`, candidate confidence, missing fields. | `IntakeDraft`, typed `PendingClarification[]`, resume token. | Required title/due time is absent or conflict is unsafe. | Local questions remain available when LLM wording fails; duplicate answers are idempotent. | `clarification-agent.ts`, `ChroniStore.answerClarification` |
| `TaskPlanGeneration` | Convert a grounded DDL into editable steps and estimates. | `DdlItem`, evidence context, selected planning preferences, optional LLM settings. | Versioned draft `TaskPlan`. | New/updated task or explicit regeneration. | Rules-only planner creates a usable draft if model is disabled, invalid, or unavailable. | `task-plan-agent.ts`, `ensureTaskPlan` |
| `PlanConstraintValidation` | Prevent a proposal from changing facts or violating local limits. | Task, plan candidate, current version. | Accepted plan/revision or validation error. | Before saving, editing, or activating a plan. | Rejects stale/invalid plans; original active plan remains. Dependency-cycle rate is not yet benchmarked because v1 schema does not encode dependency edges. | `task-plan-agent.ts`, validation/store tests |
| `LearningMissionSynthesis` | Maintain one grounded execution record for each source-driven course task. | Task, current TaskPlan, source records, previous Mission feedback. | Goal, deliverables, success criteria, milestones, progress, evidence coverage, risk and next action. | Store decode, task/source/plan update, evidence or checkpoint change. | Uses grounded extraction and rule defaults; preserves user evidence/checkpoints and removes orphan Missions with deleted tasks. | `learning-mission.ts`, `ChroniStore` synchronization |
| `EvidenceCheckpoint` | Connect real output and stage feedback to a specific Mission and milestone. | Selected local file or note; checkpoint status, milestone, effort, blocker/reflection. | Hashed file metadata or note evidence; persisted checkpoint; synchronized step/progress/risk. | Explicit user action in Learning Mission UI or authenticated note/checkpoint API. | Files are streamed and hashed in main; paths/content are not persisted; blocked requires a reason; invalid milestone/state is rejected. | `main.ts`, `validation.ts`, `store.ts`, `LearningMissionWorkspace.tsx` |
| `DailyScheduling` | Map risk-ranked work into bounded daily blocks. | Assessments, active steps, work hours, daily capacity, now. | `AgentPlan` blocks, coverage, overflow, unplanned IDs. | Manual, startup, daily, or task-change Agent run. | Deterministic `planWorkBlocks` is always available and verified after optional model planning. | `agent-tools.ts`, `deadline-agent.ts`, `agent-state.ts` |
| `ReminderDispatch` | Notify at useful moments without repeated interruptions. | Risk assessment, preferences, quiet hours, last reminder. | Sent/skipped reason plus persisted reminder time. | Learning execution Agent action or minute reminder loop. | Unsupported, disabled, quiet-hours, and duplicate outcomes are explicit; no false “sent” claim. | `agent-reminder.ts`, `main.ts` |
| `PlanningPreferenceLearning` | Reuse user-approved planning patterns under user control. | Plan edits, explicit preferences, feedback history. | Structured evidence/confidence preference records. | User saves a plan difference or edits preferences. | Low-evidence records remain inactive; users can disable, delete, or clear all memory. | `behavior-memory.ts`, Store methods, Agent workspace |
| `RunTraceExport` | Make behavior reviewable without exposing private chain-of-thought. | Structured workflow traces, latest run, snapshot metadata. | On-screen stage trace plus redacted JSON/Markdown evidence with SHA-256. | Every workflow/Agent run; explicit export action/API. | Export omits raw source, paths, task titles, keys, and free-form summaries; errors do not alter state. | `agent-trace.ts`, `evidence-report.ts`, `/api/agent/export-evidence` |

## Stable public surfaces

- Renderer IPC contracts are typed in `src/renderer/src/vite-env.d.ts` and exposed from `preload.cjs`.
- The loopback API is documented in `docs/local-api.md`, discovered through `chroni-api.json`, and protected by a per-run bearer token.
- Persistent compatibility is owned by `ChroniStore`; older snapshots are normalized and receive derived `learningMissions` without requiring a manual migration.
- Benchmark entry points are `pnpm run eval:smoke` and `pnpm run eval:goai`.

These are application capability contracts, not independent hosted microservices. Extracting them into packages is a future reuse option, not a claim about the current deployment.
