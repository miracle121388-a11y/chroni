# GOAI 评委建议专项优化说明

本轮优化直接对应评委提出的两项要求：把 Chroni 放进真实学习流程，以及证明规划会随执行结果动态变化。所有“效果变化”均来自产品内置的隔离合成案例或用户本机行为数据，不宣称真实学生成绩提升或因果效果。

## 1. 真实学习流程如何闭环

```text
群聊 / 通知 / PDF / 表格 / 图片
→ 语义理解并锁定来源时间
→ 按学业影响、截止、进度、工作量和历史执行排序
→ 拆解步骤并排入今日/未来 7 天
→ 桌宠与系统提醒
→ 用户完成、登记证据或反馈受阻
→ 每日回顾保存实际完成与投入
→ 风险、容量、提醒和下一步自动重算
```

| 学习环节 | Chroni 的实际动作 | 解决的真实问题 |
| --- | --- | --- |
| 时间规划 | 计算截止前可用容量、剩余工时和缓冲，并避开学生已安排的课程、会议和手动日程，不只按 DDL 先后排序。 | 多个截止接近时只抢最早任务，或把学习块排进已有活动。 |
| 任务安排 | 将依赖已满足的下一步骤写入今日和未来 7 天时间块。 | 计划停留在清单，学生不知道现在具体做什么。 |
| 学习提醒 | 普通高风险提醒、一次未完成恢复提醒、连续未完成重新启动提醒采用不同文案。 | 统一催促造成麻木，拖延后更难启动。 |
| 执行反馈 | 完成时间块会同步计划步骤和任务进度；历史未完成时段不会被下一次重排抹掉。 | 计划无法反映真实完成情况。 |
| 复盘与调整 | 每日回顾保存任务数、完成数、计划/完成时长和顺延项；下一轮读取这些数据。 | 每天重新做计划，却不吸取前一天执行偏差。 |

## 2. 两个用户问题的确定性修正

### 2.1 接近 DDL 不再只按时间先后

输入：

```text
社团汇报 PPT 初稿明天 9:00 在群里收；
期末作业明天 9:30 前发给老师，目前期末作业完成 20%，PPT 初稿完成 70%。
```

Chroni 现在统一计算五类信号：

1. 学业后果：期末、考试、答辩、毕业和正式课程考核高于普通社团活动；
2. 截止距离：越接近风险越高，但不再成为唯一排序条件；
3. 当前进度：接近截止且完成度低会提高风险；
4. 剩余工作量：估时与可用时间不匹配时提高风险；
5. 执行历史：近期计划未完成会提高优先级并触发干预。

因此即使社团初稿早 30 分钟，期末作业仍排在前面。该规则同时用于日程列表、Agent 风险排序、今日工作块和未来 7 天预排，避免不同界面给出互相冲突的顺序。

### 2.2 不再要求固定句式

以下自然表达现在都可识别：

- “明早九点群里收 PPT 初稿”；
- “周五 15:00 带上论文框架和导师讨论”；
- 聊天转述、项目符号、表格行和通知段落中的交付或出席安排。

智能理解不突破事实边界：标题、重要性和任务类型可以从语境判断；日历时间仍必须能从来源原文中确定。只有“下周交一下”这类时间不完整的表达会保留为待确认草稿，Chroni 不擅自补成 23:59。

## 3. 未完成计划时的分级干预

| 状态 | 系统动作 | 目的 |
| --- | --- | --- |
| 无近期未完成 | 正常按风险与容量规划。 | 保持节奏，不额外打扰。 |
| 1 个计划时段未完成 | `nudge`：建议先恢复推进 25 分钟，并随进度重排。 | 降低一次偏差演变为持续拖延的概率。 |
| 最近 14 天内连续至少 2 个计划时段未完成 | `rescue`：优先级上调，提醒先完成 15 分钟最小步骤，完成后立即重排。 | 降低重新启动门槛，不用更强的空泛催促。 |
| 近 7 天完成率或执行效率持续偏低 | 下一轮单日规划在用户设置上限内收敛为 70%–85%，最低 30 分钟。 | 避免“每天继续超排—继续失败”的循环。 |
| 超排或顺延集中 | 移走低重要性任务、保留高学业影响任务和截止缓冲。 | 修复学习节奏失衡。 |

所有干预都能在 Agent 排序理由、通知文案、工作块和每日回顾中看到；用户仍可手动调整日程或关闭提醒。

## 4. 连续使用效果如何验证

“每日回顾”新增四个本机可计算指标，并对比最近 7 天与此前 7 天：

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| 任务完成率 | 完成任务数 / 计划任务数 | 直接反映计划落地比例。 |
| 执行效率 | 完成任务对应时长 / 规划时长 | 是计划执行代理，不等同于认知学习效率。 |
| 计划未完成率 | 有顺延项的复盘天数 / 有任务的复盘天数 | 是“拖延”的透明行为代理，不作心理学诊断。 |
| 节奏平衡 | 根据超出容量的天数和每日规划波动计算 0–100 分 | 用于发现集中超排和节奏失衡。 |

产品内置“连续使用与动态干预”隔离示例，提供 14 天合成记录。固定结果为：

| 指标 | 此前 7 天 | 最近 7 天 | 变化 |
| --- | ---: | ---: | ---: |
| 任务完成率 | 50% | 89% | +39 个百分点 |
| 执行效率 | 50% | 89% | +39 个百分点 |
| 计划未完成率 | 100% | 43% | 改善 57 个百分点 |
| 节奏平衡 | 100 | 100 | 规划时长保持稳定 |

这组数据用于验证指标计算、趋势展示和干预链路可以连续运行，不代表真实用户成效。真实效果需要在知情同意的试点中预注册指标并收集足够周期后报告。

## 5. 现场验证路径

1. 在“智能整理”粘贴上面的聊天式文本，确认两项任务都被识别。
2. 打开日程或 Agent，确认“期末作业”排在 9:00 的社团初稿之前，并查看语境、进度和工作量理由。
3. 在“示例数据”载入“连续使用与动态干预”。
4. 打开 Agent，确认期末作业显示“重新启动 15 分钟”。
5. 打开“每日回顾”，查看连续 14 天、前后 7 天变化和下一轮动态调整。
6. 退出示例环境，确认正式本地数据未被覆盖。

对应自动化测试覆盖：语境排序、模型重要性降级拦截、非模板语义识别、未完成分级干预、容量收敛、历史时段保留、14 天指标计算和示例数据隔离。
