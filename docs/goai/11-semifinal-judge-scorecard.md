# GOAI 复赛评委视角评分审计

> 本文是团队依据参赛手册做的保守自评，不代表赛事官方分数。所有分值必须由现场 Demo、提交材料和最终可复现结果支撑。

## 结论

Chroni 已从“桌宠 DDL 管理器”升级为“面向大学项目制学习的本地学习执行 Agent”。最有竞争力的部分不是功能数量，而是形成了可现场证明的完整链路：

```text
课程材料 → 来源约束 → Learning Mission → 今日执行
→ 产出证据 / 阶段检查点 → 风险与下一步调整 → Trace / 脱敏导出
```

目前最大的扣分风险不是产品闭环，而是**缺少授权真实试点与真实图片/带凭据模型评测**。答辩中必须主动承认，不可用合成数据推导真实教育成效。

## 评委最可能认可的三点

1. **不是把聊天框包装成 Agent**：模型输出不能直接改状态，所有行为通过本地验证、Store 与工具执行，结果可追溯。
2. **教育立场清楚**：产品服务于执行和反思，不代替学习者提交答案；证据覆盖也不伪装成质量评分。
3. **可现场复现**：无 Key Demo、合成数据隔离、失败/冲突路径、评测命令和脱敏导出都能真实运行。

## 评委最可能追问的三点

1. **“这不还是任务管理吗？”**
   回答时直接演示完成标准、产出证据、里程碑检查点如何改变计划步骤、进度和下一步。不要只展示日历。

2. **“教育成效在哪里？”**
   不虚构成绩提升。说明当前验证的是过程闭环与工程可靠性，下一阶段将通过知情同意试点测量要求理解、计划执行、证据留存和阻塞恢复。

3. **“桌宠是不是喧宾夺主？”**
   说明它只是 ambient interface；GOAI original 模式不依赖第三方角色，核心 Learning Mission 和 Agent 在无角色模式下完整运行。

## 现场得分策略

- 开场 15 秒只讲定位、用户和教育边界，不从 OCR/模型配置讲起。
- 第一屏展示 Learning Mission，先证明“要求到证据”的差异，再展示每日时间轴和桌宠。
- 必须现场做一次检查点回写：选择里程碑 → 标记受阻/完成 → 展示步骤、进度、风险或下一步变化。
- 必须展示一次失败边界：缺失信息追问或来源冲突，证明模型没有越权。
- 指标只念刚生成的真实报告；主动指出未测项通常比回避更能建立可信度。
- 收尾把开源价值落到能力契约、评测和安全边界，不以“代码已上传 GitHub”代替复用价值。

## 红线检查

- 不展示真实学生、课程群或学校材料，除非已有可证明授权与脱敏流程。
- 不把合成 Demo 说成真实使用案例，不把证据覆盖说成质量正确率。
- 不声称自研基础模型、多 Agent、学校合作、用户规模或成绩提升。
- 不在 GOAI 赛事包中使用未获书面赛事授权的可选第三方桌宠资产。
- 不隐藏失败项、未测项、签名/公证状态或模型调用的数据发送边界。

## 冲奖优先级

1. **P0：稳定演示**。按 `04-demo-video-script.md` 连续完成 A/B/C、证据、检查点、Trace、退出隔离状态。
2. **P0：证据一致**。最终 README、发布页、视频、答辩和机器报告使用同一定位与同一组真实数字。
3. **P1：授权小样本验证**。若赛程允许，只做有知情同意、可撤回、匿名的过程可用性测试；没有完成就不写进成绩。
4. **P1：分发可信度**。完成签名/公证或至少提供校验和、provenance 与干净机器安装录像。
5. **P2：外部评审**。邀请教育、安全和无障碍方向评审能力契约与 Demo，不把建议包装成合作背书。
