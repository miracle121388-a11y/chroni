# Chroni 复赛评委问答

1. **Chroni 和 Todoist、Structured 或日历有什么区别？**
   它们通常从干净的任务输入开始；Chroni 从课程原始材料开始，处理来源、缺失和冲突，再维护目标、完成标准、里程碑、产出证据、阶段反馈与适应性重排。ICS 可把结果继续交给下游日历。

2. **Chroni 和 ChatGPT 总结/规划有什么区别？**
   一次性回答不会天然拥有来源证据、持久状态、计划版本、本地工具结果、容量、检查点和失败恢复。Chroni 的模型只提出有界候选，本地系统执行并验证状态转换。

3. **为什么这必须是 Agent，而不是固定工作流？**
   它要持续读取变化的来源、计划、现实时间、产出和阻塞，选择本地工具，验证覆盖，再根据反馈重算下一步。用户完成、受阻或修改计划后，后续行为会改变。

4. **项目为什么属于 AI + 教育，而不是效率工具？**
   Chroni 将项目制学习中的目标、完成标准、过程产出、实际投入和阶段反思放进同一任务档案，提供执行支架和元认知反馈。它不代写，也不把自动排程当作学习成果。

5. **桌宠是不是噱头？**
   桌宠是环境式入口：承接拖放、呈现理解/规划/风险状态、低打扰提醒并一键返回日程。它提升“持续在场”的交互价值，但 Learning Mission 和 Agent 闭环不依赖角色形象；即使关闭桌宠，控制中心仍可完整运行。

6. **什么是 Learning Mission？**
   它是每条来源任务的稳定执行档案，包含目标、交付物、完成标准、TaskPlan 里程碑、当前行动、产出证据、阶段检查点、来源、进度和风险。

7. **证据覆盖率是否代表作业正确或学习有效？**
   不代表。它只表示交付物是否拥有用户登记的产出记录。Chroni 当前不做学术质量自动评分，也不声称预测成绩。

8. **如何防止把原材料冒充成果？**
   来源记录与产出证据是不同 schema 和入口；同步器只计算用户显式登记的 Mission evidence。产品文案和 Demo 均明确原始课程材料不计为成果。

9. **文件证据如何处理？**
   Electron 主进程流式计算 SHA-256，只保存文件显示名、大小、MIME、修改时间、哈希、关联交付物和登记时间；不把绝对路径或文件内容写入状态。HTTP API 不接受任意本机路径。

10. **谁决定任务完成？**
    用户。模型不能写入完成状态；时间块结束也不会自动完成。用户提交完成检查点或明确标记任务完成后，本地 Store 才更新。

11. **没有 API Key 能做什么？**
    本地文件解析/OCR、明确日期抽取、条件/冲突检查、追问、规则 TaskPlan、Learning Mission、证据/检查点、每日排程、提醒、Memory 控制、本地 API、ICS/证据导出和三个 GOAI 场景都可运行。

12. **大模型到底负责什么？**
    负责复杂跨段语义理解、结构化任务/计划候选和可选的规划建议。来源核验、日期、schema、冲突、计划版本、容量、工具、证据、状态与回退由本地代码掌握。

13. **模型失败或输出非法怎么办？**
    Provider 错误会被分类展示；可处理场景回退本地规则，`plannerSource` 记录为 `rules-fallback`，本地验证通过后才持久化。评测包含非法模型输出回退用例。

14. **如何避免编造截止时间或交付物？**
    候选必须能被来源和本地日期解析支持。条件、模糊或冲突时间形成草稿；真正缺失的事实由用户补充。TaskPlan 不能改写来源任务的截止事实。

15. **为什么之前测试材料会过早追问，现在如何解决？**
    当前流程先完成可确定事实与任务拆解，再判断缺失项是否阻断执行；标题、时间、交付物已经明确时不会被模型降级为待确认。多任务材料会先保存可确定任务，必要问题随后处理。

16. **相对日期如何保证稳定？**
    确定性解析器接收参考时钟与本地时区。评测固定为 `2026-08-06T10:00:00+08:00` 和 `Asia/Shanghai`；无法唯一确定的“下周”不会被猜测。

17. **检查点如何影响 Agent？**
    检查点可绑定里程碑；`on-track`、`blocked`、`completed` 会同步计划步骤状态与任务进度。blocked 还必须提供原因，Mission 风险和下一步随后重新计算。

18. **长期 Memory 学什么？**
    只学习用户明确保存的结构化规划修改，例如时间偏好、步骤粒度、缓冲与任务类型模式；达到证据数和置信度门槛后才应用，用户可停用、删除或清空。

19. **为什么 local-first？本地存储就绝对安全吗？**
    Local-first 减少日常云传输并保留离线回退，但不消除端点风险。本机同账户进程和恶意软件仍是残余风险，因此 Chroni 限制网络、隔离 renderer、保护 Key、提供删除路径并公开威胁模型。

20. **会上传原始文件吗？**
    文件解析/OCR 在本机进行，模型调用使用必要的解析文本和结构化上下文，不直接上传任意二进制原文件。启用模型仍意味着文本会发给所选服务商，设置和隐私文档会明确说明。

21. **如何保护学生或未成年人数据？**
    默认本地、最小发送、无隐藏分析、用户可关闭模型和清除数据；公开反馈要求脱敏。当前不提供教师监控或云端班级画像。任何真实试点必须先完成知情同意、数据最小化与保留期限设计。

22. **导出的 Trace 是否包含模型思维链？**
    不包含。Trace 记录 run ID、触发器、plannerSource、结构化阶段、工具状态、风险、覆盖和验证结果；这是操作证据，不是私有 chain-of-thought。

23. **证据导出会脱敏什么？**
    默认移除 API Key/Token、来源全文与路径、任务/步骤标题、自由文本证据和检查点正文，并使用报告内稳定引用保留关系；文件附 SHA-256 供完整性核对。

24. **如何评测准确性？**
    `pnpm run eval:goai` 使用固定时钟运行 60 条版本化合成用例，输出提交、环境、数据集哈希、字段指标、追问、回退、p50/p95、失败项和未测项。真实图片 OCR 与带凭据模型质量仍单独标注未充分测量。

25. **为什么没有真实学生成效数字？**
    当前没有经过授权、知情同意且设计合理的真实试点，因此不制造用户数或成绩提升。复赛阶段证明的是产品闭环、工程可靠性和可复现评测；下一阶段才验证过程指标与教育成效。

26. **这是不是伪装成多 Agent？**
    不是。Chroni 明确描述为一个混合式 Agent。抽取器、规划器、工具、Store 和 UI 是有边界的模块，不被包装成不存在的多智能体协作。

27. **哪些代码和素材可以用于赛事？**
    Chroni 自研代码按 MIT 开源。依赖、字体和 XIAOTONG 桌宠资产分别遵循各自许可证。复赛安装包按非商业评审场景携带 219 张动态帧、完整 Apache-2.0、附加条款、回链和两次交互内可达的 About；项目不声称已取得独立商业授权，付费、赞助或其他商业发行前必须取得书面许可或替换素材。

28. **开源价值在哪里？**
    可复用的是“模型候选 + 本地事实权 + 工具执行 + 证据反馈”架构，以及能力契约、typed IPC/API、合成数据、评测 CLI、Trace、威胁模型和双端发布流程。

29. **产品是否已经生产就绪？**
    核心源码、构建、测试、打包、校验和与更新流程已实现；公开签名、公证、干净机器发布证据和长时间稳定性仍依赖凭据与后续执行。完成报告区分 source-ready 与 release-ready。

30. **下一步最重要的验证是什么？**
    第一，授权真实图片与模型评测；第二，小规模知情同意课程项目试点，测量要求理解、计划执行、证据留存和阻塞恢复；第三，签名公证、安全加固与课程平台/日历适配。以上均是计划，不是当前成果。
