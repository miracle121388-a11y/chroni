# Chroni v0.2.2 - macOS 首次启动钥匙串修复

`v0.2.2` 修复无 Developer ID 签名的 macOS 安装包在未配置任何模型凭据时，首次启动仍要求访问 `Chroni Safe Storage` 的问题。

## 下载

| 平台 | 文件 |
| --- | --- |
| Windows 10/11 x64 安装版 | `Chroni-0.2.2-win-x64-setup.exe` |
| Windows 10/11 x64 便携版 | `Chroni-0.2.2-win-x64-portable.exe` |
| macOS 12+ Universal | `Chroni-0.2.2-mac-universal.dmg` |

请同时下载 `SHA256SUMS.txt` 核对完整性。

## macOS 修复

- 无签名直装包不再为 Chroni 未使用的浏览器 Cookie 启用系统钥匙串加密，因此普通启动不会创建或读取 `Chroni Safe Storage`。
- 服务访问码和自定义 API Key 仍使用 Electron `safeStorage`。只有用户主动保存或读取已配置凭据时，macOS 才可能要求一次钥匙串授权。
- 打包验证会直接读取 Electron Fuse：ad-hoc 签名包若仍在普通启动阶段启用 Cookie Encryption，构建将失败。
- Universal 双架构、完整桌宠素材、应用图标、ASAR 完整性、隐私清单和自动更新元数据继续接受发布校验。

## 两类系统密码提示

1. 未签名、未公证应用首次放行时，Gatekeeper 可能要求当前 Mac 的管理员密码。只有配置 Developer ID 签名和 Apple 公证才能消除此安装门槛。
2. `Chroni Safe Storage` 弹窗是钥匙串授权，要求的是当前 Mac 账户登录密码，不存在需要用户知道的“Chroni 密钥”。本版已消除未配置凭据时的不必要访问。

当前 macOS 安装包仍未配置 Developer ID 签名和 Apple 公证。请只从官方 Release 下载并核对 SHA-256，然后在 Finder 中按住 Control 点击 Chroni，选择“打开”，或前往“系统设置 -> 隐私与安全性”仅允许这一次打开。不要关闭系统全局 Gatekeeper。
