# App Store 发布

把当前项目推进到用户要求的发布阶段，凭 Apple 实际状态报告结果。先识别平台与已有进度，复用已完成工作。用户说“帮我上架”包含必要准备、上传和普通送审操作；“准备上架资料”不包含最终提交。不要把本 skill 当作额外授权来源。

## 识别项目与当前阶段

读取项目规则、构建配置、发布文档、Git 状态和现有商店记录，形成一份简短的当前发布记录，沿用项目既有位置。记录以下事实，未知且影响后续操作的才询问：

- 平台和技术栈：Electron macOS、原生 macOS、iOS 或多平台；不得因为叫 App 就选择 iOS。
- 发行主体、Developer Team、会员状态和当前账号权限；公司主体与个人主体不要混用。
- Bundle ID、SKU、App Store Connect App ID、版本号和 build number；首次上传前核准身份，更新使用原有记录。
- 免费/付费/内购、发布地区、主语言、支持与隐私 URL、审核联系人、自动或手动发布。
- 现有证书、profile、签名入口、CI、网站部署来源和已上传构建状态。

不要自动套用其他应用的免费策略、六地区列表、联系人、年龄分级、Team ID、证书路径或隐私答案。已在本次会话确认的选择无需重复询问。缺失信息提问后，继续不依赖答案的检查。

## 准备可审核版本

1. 运行项目已有准备与验证脚本；修复实际阻塞，保留用户改动。确认发布包中的权限、隐私清单、版本、文案、资源和实际行为一致，不能只检查源码。
2. 以真实功能检查首次启动、核心路径、权限触发、退出行为及联网失败回退。审核所需后台必须可用；不要把开发模式可运行当作商店包验证通过。
3. 为实际平台核对 Apple 当前构建工具、SDK 和截图规格。Electron MAS 使用 [Electron MAS 签名与排障](references/electron-mas.md)；原生应用沿用 Xcode archive/distribution 流程，不移植 Electron 的配置或证书名称。
4. 生成与当前版本一致、无私人数据的截图。商店描述不得承诺未实现的功能；第三方素材和依赖许可与内容权利问题分别判断。
5. 对隐私声明逐项梳理“数据类别 → 接收方 → 用途 → 是否关联身份 → 是否追踪 → 是否满足不披露条件”。核对应用、SDK、后端日志、可选 AI 服务；不把“没有账号”“本地优先”推导为不收集或不关联。自由文本可能含姓名，哈希也不自动等于匿名。隐私清单与商店标签用途不同，均需独立核验。
6. 审核备注写可复现步骤，解释菜单栏驻留、可选模型同意、本地服务、特殊权限等真实行为。需要登录时提供可用审核方式，凭据仅进入授权的私有渠道。

## 网站与商店资料

在 App Store Connect 中填充或核对版本、类别、年龄分级、版权、截图、联系人、隐私、价格、销售范围及发布方式。按实际代码与依赖判断出口合规；不得把包含第三方 TLS/加密的应用写成“仅使用操作系统加密”。许可、备案等地区要求以当前官方规则和具体应用为准，不自行捏造，也不绕过。

支持页和隐私页必须从公网验证 HTTP 状态与正文，确认没有旧公司信息、占位内容、登录限制或带 200 状态的错误页面。核验页面内容与包内声明一致。

若需修复网站：确认当前服务、域名、源码仓库、分支、构建输出和触发方式。用户授权修复现有网站时直接完成相关修复；不要动无关 API 服务。仓库推送不等于已部署，本地上传也不意味着后续 Git 自动部署。页面操作必须以保存后的字段、部署记录和公网内容为依据；同一失败操作在检查原因并换一种合理方法后仍无效，就保留状态并交接具体一步，避免无限重试。只上传已检查的公开产物目录，排除密钥和整个私人工作区。

## 上传、关联和送审

按 [发布检查与状态判定](references/release-checks.md) 执行最后检查，使用项目已有可靠工具、官方接口或 Transporter/Xcode 上传。浏览器和原生应用操作使用环境提供的受支持工具，不硬编码历史 UI 索引、标签 ID 或会话 URL。

- 已交付后等待 Apple 处理，再查看构建详情或 TestFlight；延迟出现时不要立刻重打包或重复上传。处理失败则依据具体错误修复，按平台规则递增构建号。
- 将正确构建关联到正确平台和版本，保存并验证资料完整性。“添加以供审核”形成草稿后，还需最终“提交以供审核”。
- 正式提交前支持页、隐私页、审核后台和选中构建须可用。遵守用户指定的发布方式。若遇到新的协议接受或隐私法律声明，展示具体声明并在操作时取得确认；普通送审不增设泛化确认。
- 复用已有有效授权，不要求再次批准相同动作。登录/双重认证可交由用户完成，不在聊天索取密码、验证码；新的安全敏感访问、私密数据披露等按当前工具与系统规则处理。
- 遇到拒审，先读取完整意见与对应版本，定位事实，修复并验证后再提交；不盲目更改身份、隐私答案或反复原样送审。缺少用户决定、账号权限或外部服务时记录具体阻塞并继续独立工作。

## 收尾

维护唯一当前发布记录：应用/平台/版本/构建号、提交 ID、包哈希或验证报告、网站状态、Apple 状态、发布方式及阻塞。敏感凭据和私人联系方式不进入共享仓库。按项目规则提交和推送实际代码或文档改动，不擅自创建新仓库或分支策略。

最终简要说明已完成阶段、未完成事项与下一步。保存可验证的结果证据；“正在等待审核”不等于审核通过或已上架。不承诺审核耗时；只有用户要求持续关注时才配置后续监控。
