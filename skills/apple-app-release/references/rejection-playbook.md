# 拒审处理手册

首次上架准备审核资料或收到拒审时读取。这里将 Chroni 的实际案例转成判断分支，不能据此给所有应用复制相同权限、隐私答案或材料。适用平台仍按 [主入口](../SKILL.md) 识别。

## 先决定是否需要新二进制

读取完整审核消息、附件、被审版本/构建和当前提交状态。逐项记录“要求 → 实际事实 → 修复/说明 → 验证 → 提交位置”。多个问题分别关闭，不只修复最后一条。

| 原因 | 动作 | 构建处理 |
|---|---|---|
| 缺少用途、访问步骤、服务清单或权限功能说明，实际构建完整可用 | 补充事实、复现和已有实机证据，同步回复与 Notes | 可复用当前构建，无需为纯说明重新签名 |
| 启动崩溃、权限配置错误、资源错误、无法重开或退出等工程缺陷 | 复现、修复、针对性回归、产物检查与实机复测 | 二进制改变，递增构建号、上传、选择新构建 |
| 审核账号、后台或网页不可用 | 修复实际访问路径并验证审核员能使用 | 按是否改变包内配置判断，不假定必须重建 |
| 第三方内容或受监管业务缺少授权证明 | 核对实际许可/资质及范围，补充必要声明或合法替换 | 资料补充可复用；替换资源或功能需要新构建 |

不因为审核质疑就删除必要功能、隐藏真实数据流或修改发行身份。解释必须描述实际行为；确有缺陷就修复。正式重提仍需核对 Apple 当前提交状态，不把“已回复”当作“已重新送审”。

## Guideline 2.1：需要补充信息

Chroni 的首次审核要求以下六项，并要求同时写入回复与 App Review Information 的 Notes。其他应用以当次消息为准，不能宣称所有提交必需相同录像：

1. **真机录像**：按消息要求使用当前系统，从启动开始展示典型流程。支持账号创建时演示注册、登录及删除；有面向其他用户的 UGC 时展示所需审核、举报和屏蔽机制；有付费功能时展示访问路径。无对应功能明确说明不适用，不伪造流程。
2. **用途和受众**：解决什么问题、谁使用、提供什么价值，是否面向公众或仅特定组织。
3. **访问步骤**：从安装启动到核心结果的短步骤；必要测试账号和示例文件通过私有审核渠道提供。
4. **外部服务**：核心功能实际用到的认证、AI、模型下载、数据、支付及其他平台，说明各自用途、是否可选与需要的网络条件。
5. **地区一致性**：按功能和内容事实描述差异；只有已核实一致才确认无差异。销售地区与功能差异是两个字段。
6. **权利与资质**：适用时提供监管资质、第三方素材/内容许可和授权范围；无相关业务说明事实。

使用 [六项材料模板](../assets/review-information.example.md)，按 App Store Connect 当前字段长度约束写入；超长证据放附件并明确引用。保留后续更新仍适用的说明，置顶本次变化与修复。提供“已执行”的 QA，不把计划测试写成通过。录屏步骤与复用旧录像条件见 [录像参考](runtime-qa.md#审核录像)。

## 网络 server 权限被质疑

`com.apple.security.network.client` 用于出站，`com.apple.security.network.server` 用于接受入站连接。先核对生产代码和**被审安装版**是否监听，不靠 entitlement 文件或开发服务猜测。

- **没有入站功能**：删除多余 server entitlement，核查主程序/helper 最终签名，重新构建上传并验证出站核心功能。
- **确有入站功能**：保留必要权限，在回复及 Notes 说明用户用途、启动条件、监听地址/端口、访问方式和验证结果；有 App Sandbox Information 字段时一并更新。给审核员可复现的入口，不只说“Electron 需要”。

Chroni 的生产功能是接受本机脚本请求的回环 HTTP API，实际验证监听地址、健康接口和受保护接口的未授权/已授权结果后，补充说明并沿用原构建重提。**本机监听仍是入站功能**；端口及接口不作为其他 app 的默认值。示例命令使用占位令牌，凭据与用户数据不得进入回复、录屏或共享日志。

## macOS 原生体验被拒

Chroni 因关闭主窗口后缺少应用菜单重开入口被 Guideline 4 拒绝。修复增加原生窗口菜单与快捷键，并验证首次打开、关闭后重建、最小化后恢复且无重复窗口；之后构建 4 获批。这是该应用实际整改要求，不能推导所有 app 必须用相同菜单名或 ⌘1。

按产品模型选择可发现的原生入口。区分关闭窗口与完整退出；实际使用语音/模型等资源后，Quit 应结束应终止的进程并保存数据。构建 5 的窗口及 API 已关闭而主进程残留，属于送审前 QA 发现的缺陷，**不是 Apple 拒审原因**；修复形成构建 6 后重新实测。详见 [实机 QA](runtime-qa.md) 与 [Electron 排障](electron-mas.md)。

## 沙盒崩溃、资源与内容权利

- TestFlight 启动崩溃：读取真实崩溃日志及所有相关签名。Chroni 曾因继承 helper 多余麦克风权限崩于沙盒初始化，修复不能只改源 plist；必须查签名产物并重新真机启动。见 [MAS 签名](electron-mas.md)。
- 商店资源被替换：Chroni 的 MAS 参数曾将正式小童选成 logo/兼容资源。校验渠道选择、包内资源摘要与实际画面；错误构建不继续录屏或送审。
- 第三方素材：读取完整许可及附加条款，核对修改、分发、商业使用与署名条件；保留所需许可和来源。免费不是自动获得权利的依据。若 Apple 要求权利声明，向用户展示实际声明并沿用已取得的确认，不把第三方素材改称自有。

## 回复组织

使用审核消息语言或用户指定语言，简短说明：对应条款、事实或修复、新版本/构建（如有）、审核员操作步骤、实际测试设备/OS 与附件。与 Notes 的版本、服务和隐私信息保持一致；避免营销文案、猜测根因及无证据的“全部通过”。提交后读回正确构建与等待审核状态。

## 案例范围与依据

案例来源为 Chroni 2026-09-27 至 2026-10-11 的项目发行记录与审核消息：0.2.4 (4) 首次获批上架；0.2.5 (6) 当日等待审核。不同 app 仍逐项核验当前 [审核指南](https://developer.apple.com/app-store/review/guidelines/)、[网络权限](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.network.server) 和 [Electron MAS 指南](https://www.electronjs.org/docs/latest/tutorial/mac-app-store-submission-guide)。
