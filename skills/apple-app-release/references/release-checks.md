# 发布检查与状态判定

在上传前和正式送审前读取。应用更新只检查变化及必要不变量，不重做已确认的账户设置。

## 最终检查

| 项目 | 可接受依据 |
|---|---|
| 身份 | 当前项目、签名团队、Bundle ID、平台和商店 App 记录一致 |
| 二进制 | 最终包检查通过，版本/构建号正确，关键功能可运行，有包哈希或可追溯 CI 产物；记录实机安装身份与已测/未测项 |
| 资料 | 当前功能与文案/截图/分级一致；选中的是本次构建 |
| 隐私 | 依据真实数据流填写；应用同意流程、隐私页、隐私清单、商店标签无冲突 |
| 定价和地区 | 与本次用户决定相符；免费不能推导为没有内购，未授权时不能扩大地区 |
| 支持与审核路径 | 公网页面与所需后台可用；联系人有效；需要登录时审核方式有效 |
| 拒审修复（如有） | 对应原意见的复现已通过；回复与 Notes 一致；录像版本标注准确，工程变更已关联新构建 |
| 发布方式 | 自动/手动/定时与用户决定一致 |
| 授权 | 具体法律声明等所需确认已经取得；无未处理的实际阻塞 |

## 状态边界

| 已观察状态 | 可以报告 | 不可报告 |
|---|---|---|
| 本地打包与验证通过 | 可上传产物已准备 | 已上传 |
| Transporter/Xcode/API 交付成功 | 已交付 Apple | 已完成 Apple 处理 |
| Apple 处理完成，构建可选 | 构建可关联 | 已送审 |
| TestFlight 构建已加入测试群组 | 该群组可测试状态已核验 | 真机已安装/实测通过 |
| 实机已安装并核对构建身份 | 当前构建已安装；仅已执行的项目可报告通过 | 所有功能已验证 |
| 可供审核/审核草稿 | 资料已加入草稿 | 正在等待审核 |
| 已提交且正在等待审核 | 正式提交成功 | 审核通过/已上架 |
| 审核通过但等待开发者发布 | 已获批，待发布 | 用户已可下载 |
| 已请求发布，Apple 正在分发处理 | 已执行发布，等待分发 | 目标店面已可下载 |
| Apple 发布状态与目标店面可用 | 已在核验地区上架 | 所有地区必然同时可用 |

保留最直接证据即可，不为同一事实反复查询多个页面。服务器异步处理时有间隔地检查并报告变化；不要编造预计完成时间，也不要自行创建监控任务。

## 中断恢复

恢复时读取当前发布记录和真实外部状态，核对正在操作的应用与团队。上传成功后不重复上传，已送审后不再次提交；证书、截图、隐私确认和网站部署以有效证据复用。用户接手登录或上传后，检查实际结果再继续，不能把“已操作”直接等同于外部服务成功。

锁屏、登录过期、系统权限弹窗分别处理；它们不意味着二进制上传失败。按工具限制由用户解锁、登录或操作受限授权窗口后，从原检查点继续。用户已授权的正常录屏和应用操作直接完成，不反复让用户点击可自动化的步骤；不能借另一工具绕过已明确禁止的系统授权操作。

发布记录的 `checks.runtime.evidence` 写明安装渠道、实际构建身份、设备/OS、验证报告位置与关键结果；`checks.reviewAccess.evidence` 引用当前回复/Notes/附件。现有离线脚本只检查记录自洽，不能验证运行事实或录像内容，不能代替 [实机 QA](runtime-qa.md)。
